# Backend migration notes

The application has been detached from Base44. Supabase has not been connected yet.

## Data model to recreate in Supabase

### `enquiries`

Fields observed in the former Base44 Enquiry entity and contact form:

- `id` (UUID primary key, to be generated by PostgreSQL)
- `name` (text, required)
- `company` (text, optional)
- `email` (text, required)
- `phone` (text, optional)
- `country` (text, optional)
- `nature` (text, optional)
- `message` (text, required)
- `status` (text, default `New`; expected values: `New`, `In review`, `Responded`, `Closed`)
- `created_at` (timestamptz, default now())

Intended access model to review before enabling writes: public visitors may create enquiries; only authorised staff/admin users may read, update or delete them. Implement this with Supabase Row Level Security and a trusted staff-role model. Do not expose the Supabase service-role key in the browser.

### `profiles`

The former user entity included a `role` field with `admin` and `user` values. In Supabase, use a `profiles` table linked to `auth.users`, and do not allow users to assign themselves the `admin` role. Staff role changes must be performed through a trusted administrative process.

## Authentication

The former Base44 login, registration, password reset, social login, MFA and consent flows have been removed from the active code. Rebuild these flows using Supabase Auth after the Supabase project is created.

## Images

Some existing editorial images still use direct `media.base44.com` asset URLs. These are static media references, not backend/API calls. Copy these image assets into the project's `public/` directory or Supabase Storage before fully closing the old Base44 project.
